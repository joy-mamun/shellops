# Shell-Based System Administration Toolkit — Implementation Plan

## Plan: Educational Sysadmin Automation Toolkit

**TL;DR**: Build a beginner-friendly, monolithic shell script that provides four core admin features (user monitoring, disk cleanup, backup scheduling, health checks) with an interactive setup wizard for configuration. Target single-machine Linux administration with clear educational value and comprehensive documentation.

---

## Steps

### Phase 1: Project Structure & Initialization
1. Create directory hierarchy: `/bin/` (main script), `/config/` (templates), `/lib/` (shared utilities), `/docs/` (README, guides)
2. Initialize `.gitignore` for logs, temporary files, and sensitive configs
3. Create `README.md` with project overview, quick-start, and feature descriptions
4. Create `CONTRIBUTING.md` for educational contributors

*Rationale*: Clear structure makes code maintainable and educational.

### Phase 2: Core Framework & Utilities (Parallel safe)
5. Build `lib/common.sh` — shared utility functions:
   - Logging functions (info, warn, error with timestamps)
   - Color-coded output for readability
   - Error handling & exit codes
   - Permission checks (require root/sudo)
   - Validation helpers (check command exists, file readable, etc.)

6. Build `lib/config.sh` — configuration management:
   - Load/validate config files
   - Set defaults
   - Export config variables for use across modules

7. Build `setup_wizard.sh` — interactive configuration:
   - Present options for each feature
   - Validate user input
   - Generate config file in `/config/shellops.conf`
   - Explain each setting with educational context

### Phase 3: Feature Modules (Can run in parallel)
8. **User Monitoring Module** (`lib/user_monitor.sh`):
   - List active users with login times
   - Show user idle time
   - Display last login history
   - Alert on suspicious activity (e.g., root logins outside expected times)

9. **Disk Cleanup Module** (`lib/disk_cleanup.sh`):
   - Identify large files (configurable threshold)
   - Find duplicate files
   - Clean temp directories (e.g., `/tmp`, `/var/tmp`)
   - Analyze disk usage by directory
   - Generate cleanup recommendations (dry-run mode)

10. **Backup Scheduling Module** (`lib/backup_schedule.sh`):
    - Create simple tar/gzip backups of specified directories
    - Schedule via cron (with user approval)
    - Backup rotation (keep last N backups)
    - Generate backup manifest/logs
    - Restore functionality

11. **Health Check Module** (`lib/health_check.sh`):
    - CPU/memory/load averages
    - Disk space utilization
    - Service status monitoring
    - Network connectivity tests
    - Security updates availability
    - Generate health report

### Phase 4: Main Script Integration
12. Create `shellops` (main executable):
    - Parse command-line arguments: init, monitor, cleanup, backup, health, help
    - Source all modules from `lib/`
    - Load config from `config/shellops.conf`
    - Route to appropriate module based on argument
    - Provide help/usage text for each feature

### Phase 5: Documentation & Examples
13. Create comprehensive docs:
    - `docs/quick-start.md` — 5-minute tutorial
    - `docs/features.md` — detailed feature documentation
    - `docs/configuration.md` — config file options with examples
    - `docs/cron-setup.md` — how to schedule via cron
    - `docs/troubleshooting.md` — common issues and solutions

14. Create example config files in `config/`:
    - `shellops.conf.example` — fully commented template
    - `backup.exclude` — exclude patterns for backups

### Phase 6: Testing & Initialization
15. Create simple test script (`test.sh`):
    - Verify all modules load without errors
    - Check for required commands (awk, grep, tar, etc.)
    - Validate config file parsing
    - Run dry-run versions of all features

16. Create installation/initialization:
    - `install.sh` — copy files to appropriate locations, set permissions
    - `First-run` setup: prompt user to run setup wizard

## Verification

1. **Dependency Check**: Run `test.sh` to verify required utilities (awk, tar, cron, etc.) are available
2. **Module Loading**: Execute `shellops help` — all features listed without errors
3. **Setup Wizard**: Run `shellops init` — wizard prompts, generates valid config file
4. **User Monitor**: `shellops monitor` — displays active users and login info
5. **Disk Cleanup**: `shellops cleanup --dry-run` — shows large files and cleanup recommendations without making changes
6. **Backup**: `shellops backup --test` — creates test backup and displays manifest
7. **Health Check**: `shellops health` — generates comprehensive health report
8. **Cron Integration**: Manually configure `crontab -e` with generated cron commands, verify job execution
9. **Help System**: `shellops help [feature]` — displays feature-specific documentation
10. **Error Handling**: Test with missing config, insufficient permissions, invalid input — verify graceful errors

## Decisions

- **Monolithic entry point, modular internals**: Single `shellops` script routes to feature modules for clarity and educational value
- **Bash (not exotic shells)**: Ensures portability; educational focus benefits from common syntax
- **No external dependencies beyond POSIX standards**: tar, awk, grep, cron are assumed available on target systems
- **Interactive wizard for first-time setup**: Lowers learning curve; educational users can understand config incrementally
- **Dry-run modes**: High-impact operations (cleanup, backup) support `--dry-run` to prevent accidental data loss
- **Single-machine focus**: Simplifies design; foundation for multi-machine extensions later
- **Comprehensive logging**: Educational value + operational debugging

## Further Considerations

1. **Privilege Escalation Strategy**
   - Option A: Require full root/sudo (simplest, security risk for learners)
   - **Option B (Recommended)**: Require sudo only for privileged operations, note which operations need elevation
   - Option C: Create sudoers file auto-generated by installer

2. **Log Location**
   - Option A: `/home/$USER/.shellops/` (user-writable, good for learning)
   - **Option B (Recommended)**: `/var/log/shellops/` with fallback to user home if not writable
   - Option C: Configurable in setup wizard

3. **Cron Integration Complexity**
   - Option A: Manual cron editing instructions (most educational, requires user management)
   - **Option B (Recommended)**: Helper command `shellops schedule --enable feature` generates crontab entries
   - Option C: Manage crontab automatically (hidden complexity)
